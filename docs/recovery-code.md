# 復旧コード（暗号鍵の紙の控え）の作り方

DBは暗号化されています。**復旧コード**は、その鍵を紙に控えるための55文字のコードです。
PCが壊れたとき、Windowsを入れ直したとき、ユーザーの資格情報が使えなくなったときに、データを取り戻すための**最後の手段**です。

> **必ず、ご自身のPCで作ってください。** 他人（チャットのAIを含む）が作ったコードや鍵は、秘密ではないため使えません。
> **このコードと、PC側の鍵の両方を失うと、データは復元できません。**

## 作り方（現在の移行ツールの場合）

PowerShell（またはターミナル）で、リポジトリの `db` フォルダに移動して実行します。`sqlcipher3-wheels` が必要です（`pip install -r requirements.txt`）。

```powershell
# 1) 鍵ファイルを作る（256ビットの鍵。画面に復旧コードが表示されます）
python migrate_json_to_sqlite.py keygen C:\ibis-key\key.txt

# 2) 紙の控え（印刷用HTML）を作る。鍵そのものは載らず、復旧コードだけが載ります
python migrate_json_to_sqlite.py recovery-sheet C:\ibis-key\key.txt C:\ibis-key\sheet.html --label "事務所PC"

# 3) sheet.html をブラウザで開いて印刷する
# 4) 控えを見ながらコードを入力して、鍵と一致するか確認する（再入力による確認）
python migrate_json_to_sqlite.py check-code C:\ibis-key\key.txt "ここに紙のコードを書き写して入力"

# 5) 一致を確認できたら、sheet.html を削除する（ごみ箱も空にする）
```

- 鍵ファイル（key.txt）は、リポジトリの外（例：`C:\ibis-key\`）に置きます。**リポジトリの中には置かないでください**（登録しようとすると、自動チェックが止めます）。
- 鍵ファイルは、BitLocker などで保護したドライブに置くことを推奨します。
- アプリ化（Tauri）の段階では、初回起動時に、鍵の生成・保護（Windowsの資格情報）・復旧コードの表示・再入力による確認を、アプリが行う予定です。

## 紙の保管
- PCとは**別の場所**（金庫・鍵のかかる引き出しなど）に保管します
- 写真に撮る、メール・クラウド・チャットに保存することはしません
- 鍵を変更（ローテーション）したときは、古い控えを破棄して、新しい控えを作ります

## 書き写しのコツ
- コードには、数字の **0・1・8・9 は使われません**。迷ったら、0 は O（オー）、1 は I または L、8 は B と読みます
- 入力のときは、0・1・8 のまま打っても読み替えます。ハイフンや空白は、あってもなくても構いません
- 1文字でも書き間違えると、必ずエラーになります（誤った鍵が使われることはありません）
- 「1」が I か L か判別できないときは、「判別できません」と表示されます。控えを見て、I または L の文字で入力してください

## 復旧コードから鍵ファイルを作り直す
```powershell
python migrate_json_to_sqlite.py key-from-code "紙のコード" C:\ibis-key\key.txt
```

# セキュリティとデータの取り扱い

## 方針
このリポジトリに登録してよいのは、**ソースコード・手順書・匿名の検証データ**だけです。

**登録してはいけないもの**
- 実際の取引先名・請求書・見積金額・作業人員のデータ、Excel／CSV
- 暗号鍵（64桁の16進数）、復旧コード（55文字）、鍵ファイル、DBファイル、バックアップ
- パスワード、アクセストークン、秘密鍵・証明書

## 自動で止める仕組み（三重）
| 層 | 内容 |
|---|---|
| `.gitignore` | DB・鍵・Excel・CSV・バックアップなどを、そもそも `git add` の対象にしない |
| コミット前のチェック | `tools/check_secrets.py --staged`。有効化：`tools/install-hooks.sh`（Windowsは `tools\install-hooks.ps1`） |
| CI | GitHub Actions で、全ファイルを同じ規則で検査（フックを入れ忘れても止まる） |

**検出するもの**：対象の拡張子（.db／.key／.xlsx／.csv など）、64桁の16進数、復旧コード、秘密鍵、GitHubのトークン、AWSのキー、インボイス登録番号らしき文字列（見本の T1234567890123 だけ許可）、カード番号らしき並び。
会社名らしき文字列（「株式会社○○」）は、注意として表示します（見本の会社名は許可）。
誤検知のときは、該当行に `allow-secret` と書くと除外できます。理由をコメントに残してください。検出した値そのものは表示しません。

> この仕組みは「うっかり」を防ぐためのものです。意図的な持ち出しや、規則に当てはまらない形の情報（たとえば会社名だけ）は、止められません。レビューで確認してください。

## 検証データについて
`db/tests/fixtures/` のデータは、現行アプリの**サンプルデータ**（見本の会社名・ダミーの登録番号）から自動生成したものです。実データから作ってはいけません。
作り直すときは `db/tests/gen_fixtures.js` を使います（`app/` で `npm ci` した後、`NODE_PATH=../../app/node_modules node gen_fixtures.js`）。

## 鍵と復旧コード
[docs/recovery-code.md](recovery-code.md) を参照してください。鍵ファイルはリポジトリの外に置きます。

## GitHubの設定
- リポジトリは **Private**。フォークを許可しない設定にする
- アカウントは2要素認証にする。招待するメンバーは最小限にする
- GitHubの機能（シークレットスキャン、プッシュ保護、Dependabotのアラート）は、利用できる範囲で有効にする（プランにより利用可否が異なります。設定名は変わることがあります）

## 誤って登録・pushしてしまったとき
1. **まず、リポジトリを非公開にする**（公開になっていた場合）。他の人に見られた可能性を前提に動く
2. **鍵・トークン・パスワードの場合**：その値は漏れたものとして**使うのをやめ、新しく作り直す**。DBの鍵は `PRAGMA rekey`（または `sqlcipher_export`）で新しい鍵へ切り替え、復旧コードを再発行し、古い鍵で作ったバックアップも作り直す
3. **履歴から取り除く**：ファイルを消すだけでは、履歴に残ります。履歴の書き換え（`git filter-repo` など）と、強制push、GitHubサポートへのキャッシュ削除の依頼が必要です。すでにクローン・フォークされていれば、そちらにも残ります
4. **実データ（個人情報・取引先の情報）の場合**：どの範囲が、誰に見える状態だったかを確認し、社内の規程に従って報告・対応を判断する
5. 同じことが起きないよう、検出されなかった理由を確認して、`tools/check_secrets.py` の規則を直す

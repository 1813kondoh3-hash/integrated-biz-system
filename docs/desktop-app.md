# デスクトップアプリ（Tauri）

C案のアプリ本体です。今は**最小版**（データの準備だけ）で、次のことができます。

| 手順 | できること |
|---|---|
| 1. 暗号鍵を用意する | 移行ツールで作った鍵ファイルの取り込み／紙の復旧コードからの復元／新しい鍵の作成（復旧コードを表示し、再入力で一致したときだけ保存）／紙の復旧コードとの照合 |
| 2. データベースを作る | 保管した鍵で暗号化した、空のデータベースを作る（すでにあれば上書きしない） |
| 3. 今のデータを移す | **次の段階**（HTML版のバックアップ（JSON）を取り込む） |
| 4. バックアップを取る | 暗号化したまま、整合したコピーを保存し、同じ鍵で開けることを確かめる |

鍵そのもの（64桁の16進数）は、画面に表示しません。復旧コードを表示するのは、新しい鍵を作るときだけです。

## 1. 置き場所
| もの | Windowsでの場所 |
|---|---|
| 鍵の保管ファイル（DPAPI） | `%LOCALAPPDATA%\IntegratedBizSystem\key.dpapi` |
| データベース | `%LOCALAPPDATA%\IntegratedBizSystem\ibis.db` |

`ibis-key.exe`（確認用のコマンド）と同じ鍵の保管ファイルを使います。`ibis-key` で取り込んだ鍵は、そのままアプリで使えます。

## 2. 構成
| 場所 | 内容 |
|---|---|
| `rust/ibis-core/src/appcore.rs` | アプリの中身（状態の確認・DBの作成・バックアップ）。画面に依存しないので、Linuxでもテストできる（`tests/appcore.rs`） |
| `desktop/src-tauri/` | Tauri 2 のアプリ。画面から呼ぶコマンドを定義するだけで、処理は ibis-core に任せる |
| `desktop/ui/` | 画面（HTML・CSS・JavaScript）。ビルドの道具は使わない。外部の読み込みはなく、CSPで自分自身のファイルだけを許可している |
| `.github/workflows/desktop-build.yml` | GitHubのWindows環境でアプリ（exe）を作る（手動実行） |

ファイルの選択（鍵ファイル・バックアップ先）は、Rust側でダイアログを開きます。画面に与えている権限は、このアプリのコマンドを呼ぶこと（`core:default`）だけです。

## 3. Windows 10 での確認手順（初回）
1. GitHubの Actions →「**Desktop app build**」→「**ワークフローを実行する**」で実行する（「再実行」ではなく）。
2. 終わったら、成果物 `desktop-app` をダウンロードして展開する。`ibis-desktop.exe` と `sha256.txt` が入っている。
3. `ibis-desktop.exe` を任意のフォルダ（例：`C:\ibis-app`）に置いて、ダブルクリックで起動する。署名がないため「WindowsによってPCが保護されました」と出たら、「詳細情報」→「実行」。
4. **手順1**：すでに `ibis-key` で鍵を取り込んであるので、「鍵を正しく開けました」「保管方式：Windows DPAPI」と表示されることを確認する。「紙の復旧コードと照合する」で、紙のコードを入力して「一致しました」を確認する。
5. **手順2**：「空のデータベースを作る」を押し、「開けました（検査に問題なし）」「操作履歴 1 件」と表示されることを確認する。
6. **手順4**：「保存先を選んでバックアップする」でフォルダ（例：USBメモリ）を選び、「保存して、開けることを確かめました」と表示されることを確認する。
7. アプリを閉じて、もう一度起動し、手順1・2が「確認済み」の状態で始まることを確認する。

画面が真っ白のまま、または起動しない場合は、WebView2（Edgeの部品）がないか、古い可能性があります。その表示を共有してください。

## 4. 手元（Linux）での開発
```bash
sudo apt install libwebkit2gtk-4.1-dev libgtk-3-dev librsvg2-dev   # Tauriに必要な部品
cd desktop && npm ci
npx tauri dev              # 開発用に起動する（Rust 1.90 以上が必要）
```
Windows以外では、鍵を保護せずに保存します（開発・検証用。画面にも注意を表示します）。

## 6. 次の段階
- 今のデータ（HTML版のJSON）を取り込む機能。Pythonの移行ツールの処理（事前チェック・変換・自己検証）をRustに移し、Python版と同じ結果になることを照合してから使う
